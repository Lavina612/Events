# Event Management API

Сервис для управления мероприятиями на платформе ASP.NET Core Web API с использованием **.NET 10**.
Сервис находится на первом этапе разработки.

## 🚀 О проекте
Данное приложение представляет собой базовый REST API, реализующий полный цикл CRUD-операций для управления событиями. 
* **Архитектура**: Тонкие контроллеры, вся бизнес-логика и управление данными вынесены в слой сервисов (`EventService`) и скрыты за интерфейсом (`IEventService`).
* **Хранение данных**: Хранение в памяти приложения (`static List<Event>`).
* **Валидация**: Автоматическая валидация входных данных на уровне модели DTO с использованием встроенных атрибутов и интерфейса `IValidatableObject`.

## 🛠️ Требования для запуска
Для запуска проекта вам понадобится установленный **.NET 10 SDK** (или новее).

## 🏃 Запуск приложения

1. **Клонируйте репозиторий:**
   ```bash
   git clone https://github.com/Lavina612/Events.git
   cd <название-папки-проекта>
   ```

2. **Восстановите зависимости и соберите проект:**
   ```bash
   dotnet build
   ```

3. **Запустите Web API:**
   ```bash
   cd EventsRestApi
   dotnet run
   ```

После успешного запуска приложение станет доступно по адресам из `launchSettings.json`:
* 🔐 Безопасное соединение: [https://localhost:7226](https://localhost:7226)
* 🌐 Обычное соединение: [http://localhost:5148](http://localhost:5148)

### Спецификация эндпоинтов (REST)


| Метод | Эндпоинт | Описание | Успешный статус | Ошибки |
| :--- | :--- | :--- | :--- | :--- |
| **GET** | `/api/events` | Получить список всех мероприятий | `200 OK` | — |
| **GET** | `/api/events/{id}` | Получить мероприятие по его `id` | `200 OK` | `404 Not Found` |
| **POST** | `/api/events` | Создать новое мероприятие | `201 Created` | `400 BadRequest` (валидация) |
| **PUT** | `/api/events/{id}` | Обновить существующее мероприятие по его `id` | `204 NoContent` | `400 BadRequest` (валидация), `404 Not Found` |
| **DELETE**| `/api/events/{id}` | Удалить мероприятие по его `id` | `204 NoContent` | `404 Not Found` |

## 🛑 Правила валидации данных (DTO)

При отправке запросов `POST` и `PUT` данные автоматически проверяются по следующим критериям:
1. Поле `Title` обязательно для заполнения и не может быть пустым.
2. Поля `StartAt` и `EndAt` обязательны для заполнения.
3. Дата окончания мероприятия (`EndAt`) должна быть позже даты начала (`StartAt`).

### Пример JSON для создания мероприятия (`POST /api/events`):
```json
{
  "title": "Мероприятие 1",
  "description": "Описание 1",
  "startAt": "2026-05-10T10:00:00Z",
  "endAt": "2026-05-15T12:00:00Z"
}
```
*(Обратите внимание: `id` при создании передавать не нужно, сервер сгенерирует его автоматически методом `Max() + 1`)*.
